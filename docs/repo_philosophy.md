# Repo Philosophy

Unlearning ML is a personal machine learning gym.

The point is not to collect notebooks. The point is to rebuild practical ML intuition through small, complete, well-documented tasks.

---

## Core Principle

Every task should teach one useful piece of ML clearly.

A task is valuable when it explains:

- what problem is being solved
- what data is being used
- what baseline is being beaten
- what model is being studied
- what metric matters
- where the model fails
- what should be tried next

---

## What This Repo Is

- A structured ML practice system
- A revision guide for future study
- A portfolio of applied ML experiments
- A place to compare models across data types
- A durable record of mistakes, assumptions, and fixes

---

## What This Repo Is Not

- A dump of random Kaggle notebooks
- A place for unexplained high scores
- A leaderboard-only project
- A production ML platform yet
- A replacement for task-level reports

---

## Learning Rule

Prefer complete simple tasks over abandoned ambitious tasks.

A small task with a baseline, metrics, error analysis, and report is better than a large unfinished deep learning experiment.

---

## Documentation Rule

If future-you cannot understand the result in five minutes, the task is not documented well enough.

Each task should leave behind:

- a clear README
- reproducible code or notebook
- saved metrics
- saved plots when useful
- a final report
- tracker updates

---

## Completion Bias

The repo should reward finishing.

Do not jump from tabular regression to transformers to audio randomly. Follow the active task unless there is an explicit reason to change direction.
